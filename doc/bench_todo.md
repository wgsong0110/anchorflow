# 벤치 작업 목록 (사용자 지시 모음, 2026-10-04~05)

진행 상태를 여기에 적고 매 깨어남마다 갱신한다. ☑ 끝 · ◐ 진행 중 · ☐ 아직

## 지시 사항 (원문 요지)
1. PG · i-PG · Spring-Gaus · GASP 를 **일정 품질 기준을 만족하는 실행**으로 돌려
   FPS 를 표로. 형상 wolf·mic·lego·bread.
2. **FPS 측정은 탄성 하나만** (2026-10-04 지시).
3. **시각 품질(FID·FVD·KVD)과 물리적 옳음(물리 잔차·증분 포텐셜)은 네 물성 전부**
   (탄성·탄소성·점소성·파괴) (2026-10-05 지시).
4. 영상은 **3DGS 속성 다 써서 알파블렌딩 렌더**로. 파괴 씬은 **더 높은 데서 떨어뜨려**
   실제로 깨지게.
5. **수박 파괴 · 모래성 붕괴** 영상도 따로.
6. wolf·bread 원본 이미지가 없으면 **학습된 3DGS 에서 뷰를 렌더해** GaMeS 학습에 쓴다.
7. Spring-Gaus 는 **MPM 결과로 비디오를 만들어** 피팅에 쓴다.
8. 완료까지 **주기적으로 모니터링**하며 끝낸다 (중간에 멈추지 않는다).

## 완료 기준 (2026-10-05 지시)
**모든 방법론 × 모든 조합 × 모든 지표**. 즉 4 방법(PG · i-PG · GASP · Spring-Gaus)
× 4 형상(wolf·mic·lego·bread) × 4 물성(탄성·탄소성·점소성·파괴) = **64 칸**에 대해
물리 잔차 · 증분 포텐셜 · FID · FVD · KVD · 영상을 채운다. FPS 는 탄성만.
원 논문이 지원하지 않는 조합(Spring-Gaus 의 소성·점소성·파괴, GASP 의 파괴)은
**"미지원" 으로 비우지 않는다 — 우리가 직접 붙여서 잰다** (2026-10-06 지시).
붙인 방식은 표에 "우리 확장" 으로 표시한다: GASP 는 taichi_elements 에 CD-MPM
파괴 재질을, Spring-Gaus 는 스프링 쉬는길이 소성과 강성 0 파괴를 넣었다.

### B. 지표 — 네 물성 전부 (물성 × 형상 × 방법)
파괴 칸은 **실제로 깨지는 설정**으로 돌린다: 바닥(z=0.1) 위에서 낙하 + 격자
n_grid 200(dx 0.01) + 초기 하강속도 −6, 사다리 시작 s0=800. dx 0.02 에서는
물성이 파괴여도 주저앉기만 해서 장면이 뜻을 잃는다 (실측).
- ☑ PG·i-PG 탄성 8 칸: 물리 잔차·증분 포텐셜, FID/FVD/KVD
- ☑ PG·i-PG 탄소성·점소성·파괴 24 칸 탐색 (통과 s + 기준 궤적)
- ☑ PG·i-PG 32 칸 물리 잔차·증분 포텐셜
- ☑ PG·i-PG 32 칸 FID/FVD/KVD (파괴 두 칸은 기준 미달이라 사다리에서 한프레임
  오차가 가장 작았던 s 로 렌더: pg mic s=6394, i-PG lego s=6376)
- ☑ GASP 탄성·탄소성·점소성 11 칸 완료 (잔차 + FID/FVD/KVD + 영상).
  mic 점소성만 남음 — 탐색이 중간에 죽어 재제출 (`gqlog5/q00`)
- ◐ GASP 파괴 4 칸: **taichi 에 파괴 재질(CD-MPM)을 직접 붙였다**
  (`exe/patch_ti_fracture.py`, material_fracture=5). n_grid 200 + v0 -6 + s0 800
  으로 네 형상 탐색·측정 큐 진행 중 (`gqlog5`, `gqlog6` 양쪽에서 빈 카드를
  물어 간다 — 같은 칸이 두 번 뜨지 않게 `exe/joblock.py` 로 칸을 잠근다)
- ◐ Spring-Gaus 16 칸: 소성·점소성·파괴를 **스프링 수준 확장으로 직접 붙였다**
  (`exe/sg_materials.py`). **mic·lego 의 여덟 칸 완료**:
  - 항복 변형률은 그 스프링망의 **유효 영률**로 환산한다 (E_eff = Σk l0²/10V;
    lego 1.98e6, mic 1.53e6 — MPM 의 2e6 과 거의 같다)
  - mic 탄소성·점소성은 쉬는길이가 최대 43~47% 옮겨져 **확실히 작동**,
    파괴는 스프링의 **41%가 끊긴다**
  - lego 탄소성·점소성은 쉬는길이 변화 0% — 이 낙하에서 최대 변형률이
    0.17% 라 항복(0.5%)에 닿지 않는다. 버그가 아니라 **결과**이므로 표에
    근거(실측 변형률)와 함께 "항복 미도달" 로 적는다
  - 파괴 칸은 다른 방법과 같은 v0 = -6 (피팅된 초기속도는 너무 부드러워
    스프링이 하나도 끊기지 않았다). lego 파괴는 서브스텝 요구가 50 -> 2315
    로 뛴다 (끊김이 있는 장면의 전형)
  - **네 형상 16 칸 전부 완료** (잔차·FID/FVD/KVD·영상). wolf·bread 는 잡
    교체로 끊긴 피팅을 `--dy_reload` 로 이어 300 반복을 채운 뒤 측정했다
  - 끊긴 스프링: wolf 50.1%, mic 41.2% / 쉬는길이 변화: mic 43~47%

### F. 걸림돌 기록
- **taichi 파괴 재질이 CUDA illegal address 로 죽던 진짜 원인**: 경화계수 줄
  `h = 0.3` 이 `g2p2g` 와 `p2g` **양쪽에** 있고 주석 대소문자만 다르다
  (Jelly/jelly). 한쪽만 고치면 실제로 쓰이는 p2g 에서 파괴 입자의
  `h = exp(10(1-Jp))` 가 Jp=0 때문에 e^10 ≈ 2.2e4 가 되어 응력이 2 만 배로
  터진다. Cam-Clay 수식도 커널 자체도 무죄였다 (단계 0 이분탐색으로 확인)
- **2026-10-06 12:21 에 PBS 잡이 교체되며 돌던 것 전부가 죽었다** (GASP 탐색 5 개,
  SG 피팅 2 개). 새 잡은 같은 노드·7 장으로 바로 받았다. 교훈:
  - GASP 탐색은 중간 산출물이 없어 **처음부터** 다시 돌려야 한다 (칸당 수 시간)
  - Spring-Gaus 동역학 단계는 **이어서 돌릴 수 있다**:
    `train.py --cfg <shape>_rs.yaml --dy_reload <exp>/checkpoints_dynamic/checkpoint/Spring_Mass.pth.tar`
    + 그 설정에 `DYNAMIC.ITERATIONS: 100` (남은 반복 수). 정적·속도 단계는
    `CHECKPOINTS_ROOT` 에 산출물이 있으면 train.py 가 알아서 건너뛴다
    (train.py 804~835 줄). 체크포인트는 SAVE_INTERVAL=100 이라 100 단위로 남는다
  - 잠금 파일(`bench/.locks/`)은 프로세스가 죽으면 남는다 -- `joblock` 이 죽은
    pid 를 보고 빼앗지만, 큐를 다시 띄울 때 한 번 치워 주는 게 깔끔하다
- taichi 커널에 타입 주석 인자를 둘 수 없다 — `from __future__ import annotations`
  가 주석을 문자열로 만들어 `ti.i32` 를 못 읽는다. 인자 없이 닫힘으로 넘긴다
- GASP 잔차는 **그쪽 정의 그대로**: p_vol=dx^3 균일(셀 개수로 안 나눔), E=2e6,
  nu=0.2, rho=1000, sand 는 로그변형 StVK, snow 는 h=exp(10(1-Jp)) 경화

## 메모
- 기준 궤적은 "수렴해"가 아니라 **그 방법의 최고정밀 실행**이다 (사다리가 수렴하지
  않는다 -- 충돌 구간은 dt 민감도가 지배).
- 시간 측정은 **빈 노드에서** `p2g2p` 루프만 계측한다.
- 렌더용 실행은 **공식 채우기**(`particle_filling`)로 돌린다 (입자 주입은 가우시안을
  갈아끼워 렌더 불가).
